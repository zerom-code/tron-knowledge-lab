# TRON Knowledge Lab

Прототип тестового задания Roman Horbachov: Knowledge Base → RAG → AI Agent.
Версия 3.1.0. Backend: Python 3.12, FastAPI, SQLAlchemy AsyncIO,
PostgreSQL 16 и pgvector. Интерфейс: HTML, CSS, JavaScript.

## Запуск

Установите Docker Desktop с Linux containers. В PowerShell из папки проекта:

```powershell
Copy-Item .env.example .env
notepad .env
docker compose up --build -d
```

В `.env` задайте собственный `EDITOR_TOKEN` вместо шаблонного значения.
Для новых запросов и embeddings задайте `OPENAI_API_KEY`.
При обновлении проекта сохраните существующий `.env` и Docker volume;
повторное копирование `.env.example` не требуется.

- Приложение: http://127.0.0.1:8000/
- Состояние API и БД: http://127.0.0.1:8000/api/health
- Swagger: http://127.0.0.1:8000/docs

Для редактирования нажмите «Пароль редактора», введите значение `EDITOR_TOKEN`
и нажмите «Подключить редактора». Поле пароля доступно также в формах импорта
и сверки. Просмотр и поиск не требуют пароля. Ключ OpenAI вводится только в `.env`.

## Проверка сценария

1. В Knowledge Base откройте **How TRON Energy Rental Works**.
   Вкладки показывают chunks, факты, claims, entities, источники и версии.
2. Перейдите в RAG Search. Выберите «Сохранённые примеры» в верхней панели.
   Нажмите «Снижение комиссии», затем «Выполнить поиск».
3. Откройте «Посмотреть контекст». Здесь отображаются выбранные chunks,
   связанные факты, источники и JSON пакета.
4. Нажмите «Передать контекст AI». Ссылки `[1]` и `[2]` открывают
   использованные фрагменты документа.
5. Для отказа нажмите Low Confidence в меню: пример спрашивает точную
   комиссию на завтра, которой нет в источниках.
6. Экран «Архитектура» показывает компоненты, модель данных и решения.

Сохранённые примеры используют полученные ранее результаты OpenAI.
SQL-поиск и сборка контекста выполняются при каждом запуске. Для нового
вопроса или импортированных фрагментов выберите **Live OpenAI** и повторите
поиск. Live расходует баланс API; отсутствие сохранённой оценки не подменяется
вымышленным score.

Для импорта укажите HTTPS URL и вставьте текст статьи. URL служит ссылкой
на источник: приложение не скачивает страницу автоматически. Обработка
идёт в фоне, новые утверждения остаются Unverified. После сверки каждого
нужного фрагмента с источником нажмите «Сохранить проверку». Новый текст
может потребовать OpenAI embeddings независимо от режима поиска.

## Реализация и границы

- PostgreSQL хранит документы, версии, sections, chunks, assertions,
  evidence, entities, topics, sources, jobs, поисковые прогоны и ответы.
- Worker сохраняет этапы и ошибки. Retry создаёт новую версию того же документа;
  старая успешная версия сохраняется при неудаче новой.
- Поиск: metadata prefilters → pgvector cosine + PostgreSQL FTS / `ts_rank_cd`
  → RRF → OpenAI reranking → Context Builder.
- Контекст ограничен шестью Verified-фрагментами и 7 800 знаками текста.
  Политика требует двух релевантных фрагментов, двух подкреплённых фактов,
  источника и покрытия вопроса. При нехватке данных генерация блокируется.
- Agent получает пакет контекста. Сервер проверяет ссылки и поддержку каждого
  абзаца его собственными цитатами.

Начальный корпус: четыре документа, 22 фрагмента и восемь сверенных фактов.
Это небольшой набор источников, не полный crawl сайта. Понимание запроса и
выделение entities основаны на правилах. Порог достаточности требует калибровки.
Поддерживается один проект и простой доступ редактора. Интеграции GSC/GA4,
CMS, полный multitenant RBAC и остальные агенты V1 выходят за границы тестового.

```powershell
docker compose exec api python -m pytest -q
```

Браузерные проверки и opt-in проверки OpenAI описаны в [QA.md](QA.md).
Данные сохраняются в Docker volume. `docker compose stop` останавливает
приложение; `docker compose up -d` запускает его снова. Локальный адрес доступен
на компьютере запуска. Публичное размещение требует отдельного адреса и доступа
к работающему backend.
